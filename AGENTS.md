This is an Expo/React Native mobile application. Prioritize mobile-first patterns, performance, and cross-platform compatibility.

## Expo has changed — do not trust your training data

Expo ships breaking changes every SDK release. APIs you remember are likely renamed, moved, or removed. Before writing any code that touches an Expo, EAS, or React Native API:

1. Read the major version of the `expo` package in `package.json`.
2. Fetch the matching versioned docs: `https://docs.expo.dev/versions/v<major>.0.0/`
3. For anything else, fetch https://docs.expo.dev/llms.txt — an index of all Expo docs with corrections to common LLM misconceptions. Follow its links to the specific page you need; never answer from memory.

## Commands

Use `bunx` instead of `npx` if the project uses bun (`bun.lock` present).

```bash
npx expo install <package>  # ALWAYS use instead of npm/yarn/pnpm/bun add — resolves SDK-compatible versions
npx expo start              # start the dev server
npx expo lint               # lint
npx tsc --noEmit            # typecheck
npx expo-doctor             # diagnose dependency and config issues
npx expo install --fix      # fix incompatible package versions
```

Run lint and typecheck before declaring any task done.

## Navigation & Routing

- Use **Expo Router** for all navigation. Routes live in `src/app/` — every file there is a screen, `_layout.tsx` files define navigators. Keep non-route code (components, hooks, utils) outside `src/app/`.
- Import `Link`, `router`, and `useLocalSearchParams` from `expo-router`.
- Docs: https://docs.expo.dev/router/introduction.md

## Building with EAS

Use EAS to build, sign, and submit the app in the cloud (`eas build`, `eas submit`) and to ship over-the-air updates (`eas update`) — no local Xcode or Android Studio required. Run EAS CLI as `bunx eas-cli <command>` in Bun projects, or `npx eas-cli@latest <command>` otherwise; substitute that for bare `eas` in docs examples.
Docs: https://docs.expo.dev/eas/index.md

## Rules

- If `ios/` and `android/` directories do not exist, they are generated (Continuous Native Generation). Never create or edit them by hand — configure native behavior in `app.json` and config plugins.
- Expo Go only includes its bundled native modules. After adding a library with native code, the app needs a development build: `npx expo run:ios|android` locally, or `eas build --profile development`.
- Prefer recommended Expo modules over third-party libraries, and check your available skills before adding dependencies. Docs: https://docs.expo.dev/versions/latest/index.md

## GabAI project notes

Offline-first safety companion (Marinduque, PH). Native port of the GabAI Vite/React web prototype (formerly `project/`, no longer in this repo); `src/theme/tokens.ts` and `src/components/ui/Icon.tsx` carry over its colors, type scale, and icons.

Current architecture and implementation details are maintained in `docs/README.md` and its linked topic documents. Read those alongside source when changing a subsystem. Package manager: npm. Stack: Expo SDK 58, Expo Router, async expo-sqlite, react-native-litert-lm 0.8.1 with Nitro Modules, and an Android local Expo module at `modules/local-ai-device/`. Native AI requires a compatible development build; web uses platform-specific fallbacks. Current chat modes are local and Gemini cloud.

Verification before finishing a task: `npm run typecheck`, `npm run lint`, `npx expo-doctor`. To check bundling without a device: `CI=1 npx expo export --platform android --platform ios --output-dir /tmp/gabai-export`. Typed routes (`.expo/types`) are generated by `npx expo start`.

### Layout

- `src/app/` – routes only. `(tabs)/` = Home, Guides, Capture, AI Chatbot, Profile (custom `TabBar`, `AppHeader`, `EmergencyFab`). Root stack: `guide/[id]` (formSheet), `profile/[group]`, `settings`, `emergency`, `chat-settings` (local Gemma 4 E2B download/backend/reply length, Gemini API key/model/test, and voice preferences).
- `src/components/ui/` – themed primitives (`AppText`, `Icon`, `GroupedCard`, `ListRow`, `Button`, `Screen`, `Layout` helpers). Build screens from these; don't hard-code colors or font sizes.
- `src/theme/` – `tokens.ts` (palette, tones, spacing, type ramp, text sizes) + `useTheme()` (resolves light/dark/system and the in-app text scale).
- `src/db/` – `migrations.ts` (append-only list, tracked by `PRAGMA user_version`) and one repository module per table. Access the DB via `useSQLiteContext()` and pass it to repository functions.
- `src/storage/` – file system: photos in `Paths.document/photos` (DB stores the file *name*, never an absolute URI), JSON backup export/import.
- `src/services/` – assistant dispatch (Gemini → local LiteRT → bundled retrieval), model lifecycle, media/audio handling, speech playback, foreground location, and public updates. See `docs/ai-and-voice.md` and `docs/architecture.md` for boundaries and platform limitations.
- `src/data/` – bundled static content: guides, emergency hotlines, profile field schema. Guide text is draft and must be reviewed by medical/DRRM authorities before release; hotline numbers are also draft and need MDRRMO verification.
- `video/` – Remotion demo videos (separate npm project, gitignored). Long explainer: `npm run render` → `docs/demo/gabai-app-demo.mp4`; narration (edge-tts `en-US-AndrewNeural`, spoken as "Gabay") + music via `npm run audio` → `scripts/generate-audio.py` (needs `python3 -m venv .venv && .venv/bin/pip install edge-tts numpy`). 60 s promo (`src/promo/`, entry `src/promo/Promo.tsx`, id `GabAIPromo`): `npm run promo` → `docs/demo/gabai-promo.mp4`, preview `npm run studio:promo`. Built from real app screenshots (`npm run screens` → `scripts/capture-screens.mjs`, CDP-driven headless Chrome against `CI=1 npx expo start --web --port 8099`; persistent profile at `$PROFILE`, clock pinned 9:41 AM, weather forced daytime, web-only chat banner swapped for the native "Local AI · GPU" state) and `npm run promo-audio` → `scripts/generate-promo-audio.py` (edge-tts `fil-PH-AngeloNeural` so Gabay/barangay/Marinduque are Tagalog-native, per-word timings → `src/promo/timeline.json`, 120 BPM beat-matched music + SFX).

### Conventions

- Settings (light/dark appearance, text size) live in SQLite and are loaded asynchronously before `SettingsProvider` renders children to avoid a theme flash.
- Schema changes: add a new function to the end of `migrations` — never edit a shipped migration.
- Use `Alert.alert` for destructive confirmations; `Banner` for inline feedback.

Onboarding: first launch shows `src/app/onboarding.tsx` (welcome → required nickname → optional profile details). Settings keys `nickname`/`onboarded` gate routes via `Stack.Protected` in `src/app/_layout.tsx`; clearing app data resets `onboarded` and re-triggers onboarding. `onboarded` is never included in backups.
